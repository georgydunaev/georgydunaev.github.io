The Ten Inviolable Laws of Anti-Vibe Coding

Fundamental principles for building mission-critical software in the post-generative era.

1. Machine-Checked Certificate No software artifact is correct without an explicit, machine-checkable proof.
2. Zero Implicit Computation Proof checkers must not hide logic behind opaque normalisation heuristics.
3. Minimal TCB Kernel Trusted kernels must remain small (~20k LOC) so they can be audited by humans.
4. Deterministic Replay Every proof step and build phase must produce bit-for-bit reproducible outcomes.
5. Explicit Assumptions All axioms, premises, and FFIs must be explicitly quantified and tracked.
6. Invariant Primacy Formulate state invariants and specifications before writing or accepting code.
7. Rejection of the Vibe If an AI generates code that you cannot formally specify, reject it immediately.
8. Proof Stability Proofs must not break due to cosmetic refactoring or minor runtime updates.
9. Universal Blame Errors must point directly to the exact logical premise that was violated.
10. High-Assurance Longevity Build software to last decades, grounded in immutable mathematical truths.
